# v1.0 verification and release decision record

**Status: unverified release plan, not a v1.0 release or tag.** Phase 44 requires all of [Post-MVP Roadmap §12.1](../vision/Phoenix_Post_MVP_Product_Roadmap_v1.0.docx), reliable L2–L3 as defined by [AI Evolution §3](../vision/Phoenix_AI_Evolution_v1.0_to_v2.0.docx), stable contracts, final security/licence review and an owner-authorized tag. A code directory or passing test does not prove user-facing completeness. Complete [preview promotion](../preview/programme.md) and attach a signed evidence ledger before making a release claim.

## Compatibility contract — baseline and publication gate

**Currently implemented baseline, not a published distribution promise:** [Event Protocol v1](../protocol/events-v1.md) currently uses wire version `1.1`; consumers ignore unknown extra fields, producers add optional fields within `1.x`, and removing/changing existing fields requires v2 and compatibility tests. Event ids deduplicate at-least-once delivery; event `source` is authenticated for registered capabilities; event payloads/metadata/provenance must not carry secrets. The v1 [manifest schema](../../protocol/schemas/capability-manifest-v1.schema.json) and `validateManifest` interpret omitted `manifest_version` and `compatibility.protocol` as the v1 baseline; explicit unsupported values fail validation. Required manifest fields include id/name/version/description/license/events/commands/permissions. Reserved sources/event namespaces and undeclared command permissions are rejected. `@phoenix/sdk` retains `defineCapability`, `runExternalCapability`, `events`, `DEFAULT_CORE_URL`, `resolveSessionToken` and types for modules/manifests/external capabilities; the SDK owner is adding `CAPABILITY_MANIFEST_VERSION` and `CAPABILITY_PROTOCOL_MAJOR` as the v1 freeze constants. `sdk/capability/src/index.ts` is the authoritative exported surface at candidate sign-off. A manifest major of `1` is **not** the same thing as an npm package release version (`@phoenix/sdk` currently workspace-private at `0.1.0`).

**v1 freeze contract and conditional publication promise (confirmed with SDK owner; release owner must approve):** within protocol/manifest major 1, preserve required fields, existing meanings and accepted v1 inputs; add only optional fields or new typed event categories without silently granting permissions; consumers continue ignoring unknown fields. Breaking schema or authorization changes require a new major with migration notes, old/new fixtures and an explicitly supported upgrade interval. Once an actual SDK v1 artifact is published, document its semver public export boundary: preserve named exports and signatures within a major, add compatible APIs in a minor, fix without changing contracts in a patch, and use a major plus migration guide for breaking changes. Publication remains conditional on release sign-off, a published version and platform matrix. This does **not** imply every internal file, HTTP route, third-party dependency or UI implementation is stable. For each proposed minor/breaking change, pin an old SDK capability to a new Core and a new SDK capability to the previous supported Core; validate manifest and event schema, lifecycle callback/auth, permission decisions, idempotency and missing optional fields; record failures and migration instructions. Never relax safety validation to preserve an unsafe plugin.

## L2–L3 measured gates (decision required before release)

L2 means retrieve and reason over authorized context, with a human choosing the next action; L3 means generate a bounded plan/proposal for human approval, not execute it by default. Define a fixed, source-labelled representative set across project memory, meetings, CI and graph questions, plus adversarial prompt injection, stale/conflicting context, hallucination, permission escalation and partial failures. Label expected facts and unacceptable actions before running the model. For every candidate record suite revision, commit, task sample sizes, provider/model and locality, reviewer identity/role, counts plus uncertainty interval, redacted trace digest and comparison to the committed baseline. Report correctness, retrieval recall/MRR/nDCG, lexical supported grounding and cited evidence, unauthorised effects/leaks/bypasses, repeated-run reliability, wall-clock latency, tokens/cost, recovery and human proposal acceptance/edit/rejection. A citation with matching tokens is not proof of semantic truth; require blinded human checks on consequential claims and plan quality.

Minimum _proposed_ release decision conditions: all nine existing offline categories present; zero unauthorised side effects, leaks, policy bypasses and cloud calls in the offline suite; adversarial and benchmark pass rates 1.00 on declared scenarios, no previously passing scenario fails or disappears, no accepted safety defects. These are not statistically equivalent to 100% general reliability. Define before measurement concrete L2/L3 sample sizes and acceptable lower confidence bounds for repeated real-model success, recovery, supported/human-judged grounding, plan usefulness, latency and cost **per category**, then require a genuinely independent review of the labels and failure analysis. Run offline suite (`npx vitest run ai/evaluation`; `npx tsx ai/evaluation/src/cli.ts run`), retain the candidate report, and inspect `npx tsx ai/evaluation/src/cli.ts gate v1.0` only as a **PROPOSAL**. [Release gates](../release-gates.md#proposed-gates-not-agreed) list draft v1 thresholds (≥8 scenarios/category, supported 0.98, cited 0.995, ≤0.005 baseline regression, real-model evidence, human-labelled set, external review and owner/security/external sign-off); these are **not agreed**, and current CI prints only an informational v0.4 gate. Local real-model testing must be separately approved and never invoke a cloud model or external write as part of offline verification. If the chosen L2/L3 policy has no measured real-model, human or independent-review evidence, mark release **blocked**, not passed on scripted-model results.

## Final release decision checklist

- [ ] Beta ledger signed with artifact checksum, clean install/upgrade/rollback on each advertised OS/architecture, crash/restart and support response evidence; no claimed external cohort without consent and recorded results.
- [ ] Inventory above tested end to end, linked to versioned evidence and all blocking issues closed. Affected samples and denominators retained; known limitations published.
- [ ] Protocol and SDK freeze reviewed against actual exports and `protocol/schemas`; old/new compatibility fixtures pass and migration guide covers changed manifests/API behavior. External SDK installation/distribution documented rather than assumed.
- [ ] L2/L3 measurements and human review meet agreed thresholds; record gate proposal versus approved gate separately. No increase to L4/autonomous side effects merely because proposal numbers pass.
- [ ] Final threat-model/security and private-report process reviewed, dependency and GPL/asset inventory plus notices current, source and attribution packaged; blockers from [security review](../security-review.md) addressed or explicitly scoped away without implying support.
- [ ] Back up and test migration on copies of existing profiles; restore on rollback when downgrade is unsafe, ensure no credentials/permissions broaden and communicate irreversible loss. Preserve original user data and keep old/new database formats distinct.
- [ ] Release owner records explicit go/no-go, date, candidate digest, actual supported platform matrix, security/licence sign-offs and documented limitations. Only after go: produce reproducible artifact, verify digest/source/notices, **then** create and verify the `v1.0` tag and release notes. No tag or publication is asserted here.

**Current blockers to a v1.0 claim:** Phase 43 stage execution and independent SDK/docs install evidence are not recorded here; `@phoenix/sdk` is not a published package; the proposed v1 evaluation gate is not an approved release policy and lacks a human-labelled/external review; desktop Linux/Windows have not been built; security review documents limitations such as unsandboxed built-ins and unencrypted vectors, while graph retrieval value is not established. Resolve with evidence rather than rewriting the gate. See the repo [gap register](../gaps.md) for current component issues; this document is not a substitute for that register.
