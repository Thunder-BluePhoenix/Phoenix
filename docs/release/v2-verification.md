# v2.0 verification and release decision record

**Status: NO-GO / evidence plan, not a release or tag.** This record maps every item in [AI Evolution §26 and §27](../vision/Phoenix_AI_Evolution_v1.0_to_v2.0.docx) to an observable gate. The evidence column reflects the repository documents inspected on 2026-10-12, **not** a fresh build, test, security audit or end-to-end run. Work in Phases 51–55 may be changing concurrently; the release owner must refresh each row against a fixed candidate digest. A code path, mock, or passing package test alone is not a shipped user outcome. [Phase 55](../phases/phase-55-v2-0-ambient-ai-layer.md) requires every §26 item, the §27 anti-goal check and final security/privacy/licence review. Neither this document nor a phase milestone authorizes a tag.

## Evidence rules and decision scope

For every row retain candidate commit and artifact digest, supported OS/architecture, configuration and provider/locality, consent and test account where applicable, scenario and denominator, expected outcome, observed result, redacted audit/trace reference, reviewer, date, and blocker disposition. Use real authorized user flows and negative/adversarial cases; fixtures and local Ollama are valuable regression evidence but cannot substitute for real-service, independent or platform-specific evidence where claimed. No cloud model or external write should run for this document. Security-critical failures, missing required functionality, or unresolved licensing obligations are **NO-GO**, not an opportunity to relabel the scope. Set quality/latency/noise thresholds and representative sample sizes **before** measuring; report confidence intervals and failures, not just a pass percentage. [Release gates](../release-gates.md) distinguish the measured v0.4 offline gate from later **unapproved proposals**; no v2 threshold is already approved there. Record actual supported subset rather than claiming every platform/provider.

Autonomy is conditional: [AI Evolution §3](../vision/Phoenix_AI_Evolution_v1.0_to_v2.0.docx) calls for **selective** L4–L6, not unrestricted access. L4 bounded execution, L5 supervised multi-step workflow and L6 proactive behavior may be declared only for individual demonstrated scopes with trusted target classification, enforced policy, per-action approval where required, OS execution sandbox for executable agent/third-party paths, durable budget/cancellation and auditable verification. [Gaps Phase 49](../gaps.md) records no audited OS sandbox and executable levels unable to start; until this is remedied and independently reviewed, those levels are **not verified**. Read-only advisory and existing user-driven workflows do not prove L4–L6. A configured level is not an executed level.

- [ ] Review microphone, screen, Kage, model routing and cloud consent with real denial/revocation, provider visibility, egress capture, sensitive classification, retention and deletion of derived vectors/graph/trace/event/sync copies.
