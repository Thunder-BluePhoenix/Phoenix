Manifest v1 migration

Existing v1 manifests without manifest_version or compatibility remain supported. To make version intent explicit while preserving behavior, add both fields: 

manifest_version: "1",
compatibility: { protocol: "1" },

Keep your own version SemVer; it does not determine protocol compatibility. Preserve required events, commands and permissions arrays. Unknown manifest fields and major "2" fail closed, not migrated automatically. Event wire samples 1.0 remain readable while current SDK emits 1.1. See the protocol reference and security guidance before adding permissions. If changing versions of a distributed SDK, test both old/new candidate artifacts against a real Core upgrade pair; this checkout includes only SDK package 0.1.0.

Run corepack pnpm --filter @phoenix/sdk build then corepack pnpm --filter @phoenix/sdk check:artifact from the root before considering publication. The latter exercises a packed tarball in an isolated consumer rather than importing SDK sources.
