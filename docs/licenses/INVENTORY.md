### Transitive crates (scanned 2026-10-08)

`cargo metadata` over `Cargo.lock` lists 458 third-party crates, counting every target (macOS, Windows, Linux, Android), so it is a superset of what any one build ships. Every licence expression offers at least one GPL-3.0-compatible option. `THIRD_PARTY_NOTICES.md` at the repository root holds the licence text of every npm package that ships and every Rust crate (485 packages: 10 npm and 475 Rust crates; 233 distinct texts). It is generated from the lockfiles by `scripts/generate-third-party-notices.mjs` and CI fails if it is out of date. Copying `THIRD_PARTY_NOTICES.md` and `LICENSE` into the release bundles is part of packaging.

## Phone link and keep-awake (Phases 71 to 75)

Phases 71 to 75 added **no new npm or Rust dependency**; `capabilities/awake` (`@phoenix/capability-awake`) uses only Node's standard library and workspace packages. The phone link's TLS certificate is **built in the repository with `node:crypto`**: `core/runtime/src/phone-cert.ts` is a minimal X.509 v3 DER builder (one fixed profile, ECDSA P-256) written for Phoenix, not a library. The helper scripts, the sudoers rule, the launchd plist and the backstop (`scripts/awake/*.sh`, `capabilities/awake/helper/`) are also written in this repository. The operating-system programs the awake capability calls (`caffeinate`, `pmset`, `ioreg`, `ps`, `networksetup`, `osascript`, `open`, `defaults`, `systemd-inhibit`, `powershell.exe`, and `tmux` and `brightness` when the user has them) are run as separate programs and are not distributed or bundled. No third-party asset was added.

## MCP server, agent safety, usage, guard and port radar (Phases 76 to 80)

Phases 76 to 80 added **no new npm or Rust dependency**. The MCP server (`core/runtime/src/mcp/`) and the stdio bridge (`scripts/mcp/phoenix-mcp-stdio.mjs`) are **hand-written JSON-RPC 2.0** over `node:http` and Node's standard library; **no MCP SDK is a dependency** and no SDK or protocol schema file was copied. The checkpoint, rollback, usage, handoff and secret-guard code uses Node's standard library and the system `git` program (run as a separate program, not bundled). `capabilities/ports` (`@phoenix/capability-ports`) is a new workspace package that uses only Node's standard library and workspace packages; it adds a lockfile link, not a third-party package. It calls `lsof`, `ss`, `netstat`, `tasklist` and `ps`, which are run as separate programs and are not distributed or bundled. The secret detector patterns are Phoenix's own (`protocol/src/secrets.ts`). The field names read from Claude Code's status JSON come from its public documentation; no code or asset was copied. No third-party asset was added.

The only dependency change in this tree is a **version bump of `vite` (MIT, development only) from ^8.3.2 to ^8.3.5**, which also moved `rolldown` and `postcss` in the lockfile. It cleared three `launch-editor` advisories that failed the CI `audit` job. None of these packages is distributed with the app.

## Machine health, engineering signals, calendar, digest, focus and screenshot (Phases 81 to 85)

Phases 81 to 85 added **no new third-party dependency** (npm or Rust) and no vendored code, schema file or asset. Two **new first-party workspace packages** were added, `@phoenix/capability-calendar` (`capabilities/calendar`) and `@phoenix/capability-machine` (`capabilities/machine`), both GPL-3.0-or-later and workspace-only; they add lockfile links, not third-party packages. The code uses Node's standard library, workspace packages and the system `git` program (run as a separate program, not bundled). The local-model manager talks to Ollama and LM Studio on loopback only, using endpoint paths and field names read from their public documentation; neither is a dependency or is bundled. The calendar adapters (Google, Microsoft Graph, CalDAV, macOS) were written from the providers' public documentation and exercised only with injected fake clients; no provider SDK is a dependency and no provider was contacted. The new interface strings (`machine`, `signals`, `calendar`, `digest`, `focus`) are original Phoenix text, with nine machine-translated, unreviewed locales as in the Phase 70 section. No migration was added.
