## WER normalisation rule (fixed before any transcript was computed)

Both reference and transcript: NFC, lower-case, U+2019 → `'`; a comma between a digit and exactly three digits is removed; every character that is not a letter, digit, apostrophe or whitespace becomes a space; leading and trailing apostrophes of a token are dropped. No number-word conversion (`42` ≠ `forty-two`), no abbreviation expansion, no spelling variants. WER = (S + D + I) / reference words, word-level Levenshtein computed in the test file. The reference for a `say` sample is exactly the text passed to `say`.

## Notes added by hand after the run (not generated)

### The first measurement failed, and what was changed

The first full run of this test (before any source change) used `WhisperStdinRecognizer` exactly as it was: arguments `-m <model> -nt -np -`. With this whisper-cli build (brew whisper-cpp 1.8.6, ggml 0.13.1) every sample returned an **empty transcript** (WER 100%, all words deleted) and the non-empty assertion failed for all four samples. That raw first-run file was deleted and re-generated; the same before-result is kept in this file as the `old-args` rows (same class, arguments forced by a runner override), which were produced in the second run below, not in the first.

Diagnosis, from commands run by hand with the same binary, model and `jfk.wav`:

| arguments (stdin carries the WAV) | spawn                                             | stdout                 | stderr lines of note                                                                                              | files created in the cwd                             |
| --------------------------------- | ------------------------------------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `-m M -nt -np -`                  | Node `spawn`, stdin pipe, cwd = an empty temp dir | empty, exit 0          | `read_audio_data: read 352078 bytes from stdin`; `warning: '--output-file -' used without any other '--output-*'` | none                                                 |
| `-m M -nt -np /dev/stdin`         | Node `spawn`, stdin pipe                          | empty, exit 0          | `read_audio_data: trying to decode with miniaudio`; `error: failed to read audio file '/dev/stdin'`               | none                                                 |
| `-m M -nt -np -otxt -of - -`      | Node `spawn`, stdin pipe, cwd = an empty temp dir | the transcript, exit 0 | `read_audio_data: read 352078 bytes from stdin`                                                                   | none (the directory stayed empty; no `-` or `-.txt`) |

(A shell redirect `< jfk.wav` with `/dev/stdin` printed the transcript, a shell file redirect and not a pipe; that variant is not what Phoenix does and was dropped.) The build treats `-of -` as "stdout"; without any `-o*` option it reads the audio but prints nothing. The shipped arguments are now `-m <model> -nt -np -otxt -of - -` (`ai/multimodal/src/dictation/whisper-stdin.ts`), and the existing unit test that pins the argument list was updated, plus a check that fails without `-otxt`.

**What could and could not be verified about other whisper.cpp builds.** Only this one build (1.8.6) was run. Whether an older whisper.cpp supports `-of -` as stdout was NOT verified; an older build that treats it as a file stem could write `-.txt` into its working directory (the real-dictation test fails if a file named `-` or `-.txt` appears). Nothing here shows the arguments behave the same on Linux or Windows builds.

### Limits of this evidence

- One machine (macOS 27.0.1, arm64, Node 22.19.0), one binary and model (whisper.cpp 1.8.6, `ggml-tiny.en.bin`, English only), four samples: 1 recording of a person (`jfk.wav`, 11 s) and 3 macOS `say` system-voice sentences (Samantha, Daniel, Karen), converted by `afconvert` to 16 kHz mono 16-bit PCM. Synthetic speech is not a person; clean studio-like audio is not a room, an accent, noise or a microphone.
- Reference text for `say` samples is the sentence passed to `say`. Under the stated WER rule, errors on these samples include differences that are not recognition errors in a human reading (for example "Doctor" vs "Dr.", "June 9" vs "9 June", dropped leading "The"). The numbers are reported as computed; nothing was tuned or re-normalised after seeing a transcript.
- 62 reference words in total: the WER figures have no statistical meaning beyond "this works on these four clips".
- No live microphone, no browser/Tauri capture path, no person speaking, no hotkey and no paste: those Phase 64 criteria remain unverified.
- Filesystem observation: names, sizes and mtimes of the listed roots before and after each recognition (and the cancel run), plus a check for new files with a RIFF header or a size within 10% of the audio. It saw no created or changed entries in any watched root during the shipped recognitions. That is one run on one machine and is not proof that no audio is ever written (a short-lived file created and removed inside the window, or in another directory, would not be seen). It observes only the default whisper engine; the Parakeet engine writes a temporary WAV by design and was not run.
- Clean-up: one local model (llama3.2:latest, Ollama 0.15.5), temperature 0 set by `cleanUp`, 3 runs each, no prompt or threshold was changed. The "added numbers/names" columns use a simple heuristic of this test (a token with a digit, or a capitalised word not at a sentence start, not found in the input) and are not the code's own rule; the code's own rule (`acceptCleanup`) accepted every model reply. Observed on `say-samantha / natural`: the reply "Quarterly report is due on Thursday. We sold 1250 units in Lisbon." re-wrote "1,250" as "1250", which the heuristic lists as an added number token (same value, different formatting; the code's rule did not object).
