## Scenario

A synthetic text file (`release-notes.txt`, below) was stored with `POST /api/attachments` (kind `text`, origin `drop`: the route the web drop uses once the page has read the file) and asked about with `POST /api/attachments/ask`: three questions x 3 runs, `temperature 0`. AI was switched on with `POST /api/ai/settings`. No vision model exists on this machine (only llama3.2 and nomic-embed-text are local); none was pulled and `PHOENIX_VISION_MODEL` was not set.

```
Lighthouse 2.4 release notes (draft, 14 March)

Version 2.4.0 ships on 28 March. It adds offline mode for the mobile app and a new CSV export.
Breaking change: the /v1/reports endpoint is removed; clients must move to /v2/reports.
The migration deadline for partners is 30 April, after which /v1 returns HTTP 410.
Known issue: CSV export times out for workspaces with more than 50,000 rows.
Contact: release manager Ingrid Solberg.
```

## Guarantees asserted and held (9/9 asks)

- HTTP 200, provider `ollama`, locality `local`, model `llama3.2`, `vision_model` null, `sources` = the one dropped file.
- In all 9 requests sent to Ollama the file text appears only in the user message (inside the nonce-tagged data block), never in the system message.

## Answer quality (execution 3; execution 2 gave the same answers)

- "Which endpoint is removed and what must clients move to?" -> "The /v1/reports endpoint is removed. Clients must move to /v2/reports." (correct 3/3; one run joined the sentences with a comma)
- "What is the deadline for partners to migrate?" -> "The migration deadline for partners is 30 April." (correct 3/3)
- "What is the cost of the enterprise plan?" (not in the file) -> "There is no information about the cost of an enterprise plan in the attached material." (correct refusal 3/3)
  Nothing wrong was observed. Three easy questions on a 7-line file is a small sample; it says nothing about long files, harder questions or hostile content.

No vision model (llava etc.) is installed, so the image -> description -> answer path has NOT been run with a real model. Only the clear 409 refusal was shown. The native/browser drag-and-drop gesture is also not exercised (the test POSTs the text the page would send).
