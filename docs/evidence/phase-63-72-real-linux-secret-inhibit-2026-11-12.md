# Phases 63 and 72: Linux Secret Service and `systemd-inhibit`, run for real in containers (2026-11-12)

Raw record: [phase-63-72-real-linux-secret-inhibit-2026-11-12-raw.json](phase-63-72-real-linux-secret-inhibit-2026-11-12-raw.json).
Harness: `core/persistence/test/real-linux/run-in-container.sh` (manual, Docker, not run by vitest or CI; one run end to end gave the records below). Ubuntu 24.04.5 LTS aarch64 containers under Colima, image `ubuntu:24.04` (local, never pulled), packages from apt: `libsecret-tools` 0.21.4, `gnome-keyring` 46.1, `dbus` 1.14.10, `systemd` 255.4, Node v18.19.1 (Ubuntu's apt Node; the production TypeScript was bundled on the host with esbuild, `node:sqlite` stubbed and `Promise.withResolvers` polyfilled for Node 18 in the harness only).

**What this is not.** A headless container keyring unlocked with a throwaway test password (`gnome-keyring-daemon --login`), on a private `dbus-run-session` bus, as root. It says nothing about a real desktop session (the unlock prompt, KWallet, a locked login keyring, a user without D-Bus), Windows, or a real laptop that sleeps. No real provider key or provider was used; fake values come from random bytes at run time and the record carries lengths and SHA-256 prefixes only.

## Part A: Secret Service (Phase 63 row, Phase 60 secret store)

Production `KeychainSecretStore("linux")` -> real `secret-tool` -> gnome-keyring. A recording wrapper first in `PATH` logged argv, the exit code and, while the real tool ran, `/proc/<pid>/cmdline` of the real `/usr/bin/secret-tool` (35 samples; the real tool's stdin was held open 0.5 s after the value so the sample was taken while it was alive).

## Part B: `systemd-inhibit` (Phase 72 Linux hold)

| Check                                                                                                                                                                        | Observed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Plain container, `systemd-inhibit --what=idle sleep 1`                                                                                                                       | `Failed to connect to bus: No such file or directory`, exit 1 (no logind)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Container with systemd as PID 1 (`docker run --privileged --cgroupns=host ... exec /sbin/init`; Colima VM only, no socket or host path mounted)                              | `systemctl is-system-running` = `running`, `systemd-logind` active; `systemd-inhibit` works                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Production `SessionController` + `createInhibitor(realEnv())` (child process bundled as `capabilities/awake/test/support/real-linux-awake-child.ts`), 1-minute timed session | `systemd-inhibit --what=idle:sleep --who=Phoenix --why="Phoenix keep-awake session" sleep 60` (child of the host process) with `sleep 60` under it; `systemd-inhibit --list` showed `Phoenix  idle:sleep  "Phoenix keep-awake session"  block`                                                                                                                                                                                                                                                                                                                                                                     |
| **SIGKILL of the host (Core)**                                                                                                                                               | the host died; `systemd-inhibit` was re-parented to PID 1 and **kept holding**; the inhibitor stayed in `--list` until its own `sleep 60` ended: **gone 58 s after the SIGKILL** (the piece was 60 s). Nothing ties the Linux child to Core (no `prctl(PR_SET_PDEATHSIG)`, no `-w` equivalent). So after SIGKILL the hold lasts for the remainder of the current piece, up to `MAX_HOLD_PIECE_SECONDS` = 30 minutes in a real session: the gap row's claim is confirmed by direct observation of the mechanism (the 30-minute length itself was not waited out; the piece is whatever `sleep N` was started with). |
| SIGTERM of the host                                                                                                                                                          | the hold survived too (the host's `process.once("exit")` kill handler does not run on a default SIGTERM, which Node does not turn into `exit`); gone only when its `sleep` ends                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Renewal (a 60-minute session, controller timers run 60x faster so the 15-minute renewal fires after 15 s; `now()` and the `sleep N` stay real)                               | a new `systemd-inhibit ... sleep 1800` appeared every 15 s and the previous one was released after the new one existed (make before break): at 5 s pid A, at 15 s pid B, at 30 s pid C, exactly one Phoenix inhibitor listed in each sample after the swap. The 30-minute `sleep 1800` pieces were requested exactly as in production. SIGKILL of the host during this left the current 1800 s piece holding (observed until the harness killed it).                                                                                                                                                               |
| Clean end through the controller (`end("cancelled")`)                                                                                                                        | `awake.session.ended` reason `cancelled`; no Phoenix inhibitor left                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

What was NOT observed: a real laptop actually refusing to idle-sleep or suspend while the inhibitor is held (the container has no power management; only logind's inhibitor list was read), a desktop session's own inhibitors, battery readers, Windows. The renewal test sped up the controller's timers (the real 15-minute wait was not run).
