## Goal

Hold a key anywhere, speak, release: the words are typed where you are, recognised on your machine.

## Tasks — parity with Coucou

- [x] Hold-to-talk global key (right ⌥ / fn / right ⌘ / right ⌃ on macOS, right Ctrl elsewhere); two taps for hands-free; Esc cancels; paste-again shortcut; clipboard restored. The state machine is pure and has 89 unit tests (`apps/desktop/src-tauri/src/dictation_keys.rs`: hold at 250 ms, double-tap window, Esc consumed only while capturing, paste-again chord, auto-repeat, bounce); the platform listeners are in `dictation_hotkey.rs` (16 unit tests on decoding and modifier tracking); clipboard restore is in the paste decision table `dictation_paste.rs` (tests "pastes_then_restores_the_original_text_after_the_delay", "the_clipboard_is_not_restored_when_the_user_copied_something_meanwhile", "a_non_text_clipboard_is_never_overwritten_and_the_text_is_typed"). Caveats: the listeners (macOS CGEventTap, Linux XRecord, Windows low-level hook) were never fed a real key press by a person; the Windows hook was never compiled; Wayland is refused. Paste-again asks Core again on every press (dictation enabled and kill switch; `pill.rs` "paste_again_refuses_and_forgets_the_text_when_dictation_is_off_or_killed").
- [ ] Offline recognition (Parakeet where available, OS speech fallback). Two recognisers are built; neither has recognised real speech in a test. **Whisper (default):** `WhisperStdinRecognizer` (`ai/multimodal/src/dictation/whisper-stdin.ts`) pipes a WAV built in memory to `whisper-cli` over stdin (`-`), selected with `PHOENIX_WHISPER_MODEL_PATH`; the real binary was first run with a stub model (bytes read from stdin). **Measured once on real speech (2026-11-11, one machine):** whisper.cpp 1.8.6 with `ggml-tiny.en.bin` (English tiny), four clips (the `jfk.wav` recording of a person plus three macOS `say` synthetic-voice sentences with numbers and a proper noun), pooled word error rate 9.7% (6 / 62 words; jfk 0%, the three `say` clips 7.1%, 16.7%, 21.4%) under the normalisation rule written in the test before computing. The measurement also found a real defect: with the arguments the code shipped (`-nt -np -`) this whisper-cli build exits 0 and prints nothing on stdout, so every transcript was empty (WER 100%); the arguments are now `-nt -np -otxt -of - -` (stdout, no file; only 1.8.6 was tried, older builds unverified). No live microphone and no person; see the [evidence](../evidence/phase-64-real-dictation-2026-11-11.md). **Parakeet (owner opt-in):** `ParakeetSherpaRecognizer` (`parakeet-sherpa.ts`) runs NVIDIA Parakeet through sherpa-onnx's `sherpa-onnx-offline` with `--tokens= --encoder= --decoder= --joiner= --model-type=nemo_transducer --num-threads=` and one WAV file argument (argv only, no shell). The flags, the WAV-only input ("single channel with 16-bit encoded samples") and the output were read from the official docs, https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-transducer/nemo-transducer-models.html, and `sherpa-onnx/csrc/sherpa-onnx-offline.cc` (logs on stderr; one JSON line `{"lang":…,"text":…,"tokens":[…]}` per file on stdout); the test fixture is copied from that page. Enabled only when `PHOENIX_SPEECH_ENGINES` lists it (default `whisper`) and `PHOENIX_PARAKEET_MODEL_DIR` (an absolute directory with `encoder[.int8].onnx`, `decoder[.int8].onnx`, `joiner[.int8].onnx`, `tokens.txt`) is set; the path is from the environment only. `ChainedRecognizer` (`speech-engines.ts`) walks the owner's ordered list: the first AVAILABLE engine runs; it falls back only when an engine is unavailable, never on an empty or failed transcription. Status (`recognizer.engines`, `recognizer.detail`) shows every listed engine, which is active and why. **OS speech fallback: not built, by decision.** macOS `SFSpeechRecognizer` needs a signed app with the speech-recognition entitlement and usage string plus a system permission prompt, is only on-device for some locales (otherwise Apple's servers: a network path), and is not callable from the Node core; Windows and Linux have no stock offline, scriptable speech-to-text program. Tests: `parakeet-sherpa.test.ts` (fake exec seam: argv, doc-fixture parsing, hostile output, timeout and size bound, temp cleanup on success/failure/timeout/cancel, selection and fallback order). Nothing here ran a real sherpa-onnx or a real Parakeet model.
- [x] Dictionary, replacements, snippets; optional AI clean-up per app (as said / natural / polished): `ai/multimodal/src/dictation/vocabulary.ts`, `cleanup.ts`, `text.ts`; per-app modes in settings. **Run once with a real local model (2026-11-11):** `llama3.2:latest` through `cleanUp` → `cleanupGenerateWith` → `AiService` (loopback Ollama only), the four real transcripts, modes as_said / natural / polished, 3 runs each: `as_said` never called the model; every natural and polished reply was accepted by `acceptCleanup` (24 of 24); the outputs are in the [evidence](../evidence/phase-64-real-dictation-2026-11-11.md). Examples: polished turned "Tell Priya Raghavan that invoice number 4821 was paid on 9 June." into "Priya Raghavan, invoice number 4821 was paid on 9 June." (drops the instruction verb), and natural on the jfk clip changed "ask what you can do" to "but what you can do" (a changed word accepted by the guard). One small model, no tuning, not a quality claim. Tests: `dictation-pipeline.test.ts` (dictionary, replacements, snippets, clean-up guard, prompt injection), `dictation-sessions.test.ts` ("uses the per-app clean-up mode"), `apps/web/test/dictation.test.tsx` ("edits dictionary, replacements and snippets…", "per-app clean-up modes…"). Clean-up is local-only by construction: its purpose is outside the sensitive-cloud allow-list, so even with the grant and every opt-in no cloud request is made (`dictation-pipeline.test.ts` "AI clean-up is local only by construction", `core/runtime/test/dictation.test.ts` "dictation clean-up never reaches a cloud provider"). Clean-up quality with a real model was not evaluated.
- [ ] The pill: see-through toolbar at a screen edge (dictate, record a call, open Phoenix); dots follow your voice. Built (`apps/desktop/src-tauri/src/pill.rs`, `pill_geometry.rs`, `apps/web/src/pill/`; tests `pill.test.tsx`, `pill-shell.test.ts`, Rust unit tests) but left unticked: nobody saw it on a screen; "Record a call" only opens `/notetaker` and starts nothing; and the pill's own **Dictate** button starts a session without the focus capture that only a hotkey start performs, so a paste from it is refused (`no_focus_target`) and the text is shown instead.
- [x] Statistics: words, time saved, WPM, streak, apps. Aggregates only, one row per local day and app in `dictation_stats` (migration 27): counts, no text, no audio, no finer time; deletable. Tests: `dictation-sessions.test.ts` ("statistics math"), `core/runtime/test/dictation.test.ts` ("dictation statistics": aggregates only, delete-all, time saved from the typing-speed setting), `dictation.test.tsx` ("shows statistics and deletes them only after a confirmation"). **Retention (user-set, default keep-until-deleted):** Settings > Dictation > "Keep statistics for" offers *Until I delete them* (the default, `null`: nothing is ever pruned, unchanged behaviour), 30, 90 or 365 days; `GET`/`POST /api/dictation/stats/retention` (session token; the body is exactly `{retention_days: null|30|90|365}`, anything else is a 400; stored under the settings key `dictation.stats_retention`, separate from `dictation.settings`). `DictationRuntime.pruneStats()` runs at Core start and once a day on the injected `Timers` (`dictation.timers`/`dictation.now` runtime options in tests) and runs `DELETE FROM dictation_stats WHERE day < cutoff` only, where the cutoff is the local calendar day N days before today: a row dated exactly N days ago is kept, N+1 is deleted. Saving a shorter period does not prune at once; the next run (Core start or the daily timer) does. Each pass that deletes rows writes one `dictation.stats.retention_prune` audit entry with `{retention_days, rows}` (no content, no app id); changing the setting writes `dictation.stats.retention`. The privacy inventory lists `dictation_stats` (row count and period). Tests: `core/runtime/test/dictation-retention.test.ts` (fake clock and hand-driven timers through `startCore`: boundary at 30/90/365, default prunes nothing, shorter period prunes on the next run, daily rescheduling, start-up pass, other tables untouched, invalid values and extra fields rejected, token required, inventory) and `dictation.test.tsx` ("saves a chosen statistics retention"). Mutation checks (each fails the named tests): `<` to `<=` or a one-day shift in the cutoff fails the boundary tests; making the default 30 fails the default/none tests; removing the start-up call fails the start-up and boundary tests; accepting 7 fails the validation test. **The owner still decides what the default should be**: this change deliberately keeps the default at keep-until-deleted, so no one's data is deleted without their own choice. Strings are machine-translated and unreviewed in the nine non-English locales. Nothing here ran on a real day-long Core; the daily timer is verified with a fake clock only.
- [x] Dictate in the chat box: `DictateButton` in `Chat.tsx` (`apps/web/src/components/Dictation.tsx`); the microphone and Core are untouched until the click. Tests: `dictation.test.tsx` ("Dictate button", "browser microphone seam", "Chat box wiring"). Tested with a fake microphone; no real browser microphone permission prompt was answered.

## Tasks — Phoenix improvements

- [ ] Dictate an instruction straight to a coding agent session. **Not built, by decision.** The flow would be a web-only one (the transcript shown in an editable box, a session picked from the tracked list, then the existing `agents.session.send` command with its confirmation), and every part of it except one is reachable with existing routes: review and edit before sending, no auto-send, an explicit session choice, the same secret check Core already applies to command input (`findSecrets` in `core/capability-manager/src/manager.ts`), and Core's kill switch, which refuses `session.send`. The part that is not reachable is that the confirmation shows the dictated text. The approval card for `session.send` is built by the capability manager from `commandTargets`, which includes only `*_id`, `id`, `project`, `target` and schema-flagged properties, clipped to 80 characters; `session.send`'s `message` is not flagged, so the card says "Send a message to a running coding-agent session [session_id: ph-…]" and never contains the message. Flagging `message` would show at most its first 80 characters, not the full text. The card also carries no field that ties it to the send this page made (`operation_id` is not returned by `GET /api/confirmations`), so a card raised by anything else that holds the session token for the same session looks identical. Because the person would approve text they cannot see in the approval, and could approve someone else's card for the same session, the dictation-to-agent flow is not built. Nothing was run: no microphone, whisper run, agent session or approval. See the gap register.
- [ ] Works on macOS, Windows and Linux (X11 and Wayland) from the first release. Not met. The paste refuses when it cannot prove the focused field is not a protected one: only macOS has a positive signal; on Linux every paste is refused, on Windows only a standard `Edit` control can be proven safe (browsers and custom controls are refused), and Wayland has neither key listening nor paste. In practice dictation paste is a macOS feature today. The Linux and Windows code compiled in CI or a container at best; none was run by a person.
- [x] Visible listening indicator in every Fawkes view: Core publishes `dictation.listening` when a session starts and `dictation.idle` on every exit path, and maps them to the LISTENING state with no timeout, so every view that mirrors Core's state shows it for the whole capture (`core/runtime/test/dictation.test.ts` "LISTENING is shown for the whole capture…", "…even before any audio, and cancel ends it", "the kill switch aborts a capture at once… and clears LISTENING"). The page itself shows a "Listening: your microphone is on" indicator (`dictation.test.tsx`). These events cannot be forged or cleared over `POST /api/events` (see Phase 65 tests `notetaker.test.ts` "the microphone indicators cannot be forged or cleared over the API"). Not looked at in each view on a real display.

- Local speech engine integration: whisper.cpp over stdin (default); Parakeet through `sherpa-onnx-offline` as an owner opt-in (writes a private temporary WAV, reported as `audio_on_disk`); fake-tested only

## Exit criteria

- [ ] Dictation pastes correctly into three different apps on macOS. Not done: the paste was never run into any application. The paste decision table and typing plan are tested with a fake platform only.
- [ ] No audio is written to disk. Not demonstrated end to end, and no longer true for one opt-in engine. With the default (whisper.cpp) dictation has no audio file: audio lives in memory and is zeroed on every exit path (`dictation-sessions.test.ts`), and whisper-cli is given `-` and no `-f`/`-o` argument (`whisper.cpp over stdin` test, fake runner). **Parakeet is the exception:** `sherpa-onnx-offline` only reads a WAV file, so when the owner opts in and it is the active engine the audio is written to a private temporary directory (mode 0700 on POSIX; the per-user temp dir on Windows, where modes do not apply) as a 0600 file, overwritten with zeros and removed on every path (test: `parakeet-sherpa.test.ts`, fake runner, real temp dir); the status says `audio_on_disk: true` and the Settings panels show a notice. A crash or power loss between the write and the erase would leave the file (not tested; the OS temp dir is cleaned on its own schedule). **Observed once (2026-11-11, macOS, whisper.cpp 1.8.6, 4 clips, plus a `cancel()` run):** the OS temp dir, `/tmp`, `/var/tmp`, the process cwd and the Phoenix data directories were listed (names, sizes, mtimes) before and after each real recognition: no entry was created or changed, and no file with a RIFF header or an audio-sized size appeared, with the shipped whisper engine. One run on one machine is not proof (a file created and removed inside the window, or elsewhere, would not be seen); the Parakeet engine was not run. `cancel()` mid-run killed the real `whisper-cli` child within 57 ms and `pgrep` found none before or after. See the [evidence](../evidence/phase-64-real-dictation-2026-11-11.md). The older `LocalWhisperSpeech` (Phase 54 one-shot capture) still writes a temporary WAV; dictation does not use it.

## Implementation notes

- **Core.** Off by default; `POST /api/dictation/sessions` starts a session, audio goes over a single-use same-origin WebSocket (`core/api/src/dictation-socket.ts`; missing or foreign origin, wrong token, a cookie, extra query parameters are refused; the socket cannot send text), `finish` returns the text. Limits: 120 s, frame size, rate; the kill switch and turning dictation off abort a capture and zero the audio. Audit entries carry no text. `dictation.listening` / `dictation.idle` are Core-only events.
- **Shell paste (`dictation_paste` command).** Only the pill window may call it. Text is refused if it contains a newline or tab (so a dictation can never press Return or Tab), if no focus target was captured when the dictation started (hotkey starts only), if focus moved, or if secure input cannot be proven false. The captured target is single use. Paste-again re-asks Core every time. These came out of a static security review and were mutation-checked for the secure-input refusal and the paste-again gate.
- **Tests.** 278 Rust unit tests across the desktop crate plus the lifecycle tests on the mock runtime (macOS), and a Linux container pass of fmt, clippy and tests at the time of the first finish; TypeScript tests listed above. Real Rust-side behaviour on Windows is unverified.

What was not done or not run: any real microphone, system hotkey, permission prompt (Accessibility, Input Monitoring, microphone), paste into an application, recognition of real speech beyond a stub-model stdin check, a real sherpa-onnx or Parakeet run, the OS speech fallback (decision), dictate-to-agent (a decision, not an omission: the `session.send` approval does not show the message; see the task above), the three-apps exit run, Linux or Windows behaviour on a desktop. Dictation start has no per-use human-bound consent beyond the standing Settings opt-in (the session token cannot tell a person from an agent). Open items are in the [gap register](../gaps.md).

## Notes & risks

- Phoenix uses its own assets; nothing from Coucou's asset list (names, Mochi, sounds, icons, media).
- Any copied or closely translated MIT code keeps its notice and goes in the licence inventory.
- Side effects go through the permission/tool gateway and the audit log; untrusted content is data, never instructions.
- Off by default; microphone permission requested on first use.
- The dictated text is on the system clipboard for about 350 ms during a paste and is then restored; another process can read it in that window.
