# Calendar awareness and meeting preparation

The read-only calendar capability supports injected Google Calendar, Microsoft Graph, CalDAV, and macOS Calendar adapters. A host must supply authenticated, consented clients or a permission-checked macOS runner; importing the capability does not contact providers. Calendar content is untrusted data, not instructions. Private events expose only a busy placeholder. Five-minute reminders are issued once per occurrence and start time, and that fact survives a Core restart (see "Reminder de-duplication" below).

Meeting preparation finds previous related meetings and reviewed decisions and open action items. The runtime query (`StoreMeetingPrepQuery`) reads accepted reviewed items of prior meetings with matching participants and is gated on `allow_sensitive_meetings`; project-only matching returns nothing because meetings carry no project field. No transcript is fetched for this feature. The notetaker button only navigates to `#/meetings`; it never starts a recording. A reminder becomes a notification ("A meeting is starting soon") through the always-notify list in `core/notifications`; it is never stored as a durable event.

A deploy freeze applies only when the user enables the calendar `freeze` setting (default false). When it is on, the `CapabilityManager` `preflight` hook runs after approval and before dispatch and refuses commands with side effect `production` and `vercel/redeploy` unless a fresh feed shows no freeze window; it fails closed (`SECURITY_POLICY_BLOCKED`) when the feed is missing, stale, unreadable or incomplete, or a credential is missing. In production no adapter is wired (`createCalendarCapability()` is called without adapters), so with the freeze on every such command is blocked. Not covered: agent permission-request approvals (AgentApprovals) and other external side effects (n8n, terminal). The host must still supply real consented provider feeds.

All present test evidence uses injected fake providers and store records; no live account or real calendar delivery has been exercised. Phase 83's exit criterion, **a real calendar event triggering a reminder and a prep note**, remains unmet until account integration and an end-to-end run are completed.

The feed fails closed. A configured provider with a missing credential, a failed or paginated read, truncation, or any unreadable event makes the whole feed unavailable; Core reports `status` as `unavailable` or `stale` and the page says so rather than "No upcoming meetings". The freeze snapshot always requests a fresh read. A blocked deploy raises `PhoenixError(SECURITY_POLICY_BLOCKED)`. Freeze markers are listed in `capabilities/calendar/README.md`.

## Reminder de-duplication

A reminder is keyed by a SHA-256 digest (first 32 hex characters) of the occurrence id and its start time, so a rescheduled meeting is reminded again but a restart is not. Core lends the capability one settings key, `calendar.reminders.sent` (`core/runtime/src/calendar/reminder-store.ts`, passed through `builtinCapabilities(..., { calendarReminders })` and wired in `main.ts`), holding `{ "version": 1, "sent": [{ "key", "start" }] }`: the opaque key and the start time in epoch milliseconds, never a title, id, attendee or link. Records are dropped once the start time has passed, and at most 500 are kept (latest starts win). Stored data is untrusted: anything that is not that exact shape, including unparseable JSON, malformed entries and a record dated further ahead than the five-minute window, is ignored.

If the store cannot be read or written, the reminder is still sent once (a missed meeting reminder is worse than a repeated one) and nothing is logged, because nothing in that path may carry event content; the in-memory record still prevents repeats in the running process. Without a `reminderStore` option (tests, other hosts) de-duplication is in memory only. Tests: `core/runtime/test/calendar-reminders-restart.test.ts` (a real `PhoenixRuntime` restarted on the same SQLite file) and the "persisted reminder keys" cases in `capabilities/calendar/test/calendar.test.ts`. Both are simulated evidence with a fake calendar.
